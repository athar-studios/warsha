### الأقسام الأربعة

| القسم | ما يدخله |

| أُضيف (Added) | ميزة أو ملف أو واجهة جديدة للمستخدم |

### قواعد الصدق

- كل بند يبدأ بفعل، ويصف ما هو موجود في المستودع الآن — لا ما ننوي إضافته.
- لا رقم بلا قياس: عدد الوكلاء (12) وعدد المراحل (14) والبوابات (4) كلها تُقرأ من ملفات

## English

The public changelog. One page, four sections, every entry tagged with the milestone (`M0`–`M19`)
that produced it and phrased in the past tense only when the change is in the repository today.
No release tag exists yet, so everything below sits under **Unreleased**; the entries move into the
`v0.1.0` section unchanged when the first tag is cut.

### How this page is produced

Entries come from the repository's conventional-commit messages. The commit type picks the section:

| Commit prefix | Section |
|---------------|---------|
| `feat:` | Added |
| `refactor:`, `perf:`, `docs:`, `style:`, `build:`, `ci:`, `chore:`, `test:` | Changed |
| `fix:` | Fixed |
| `revert:`, `remove:`, or a `!` breaking change that deletes a surface | Removed |

```bash
# The commit titles this page is generated from, newest first.
git log --no-merges --pretty='%h %s' -- . | grep -E '^(.*)(feat|fix|docs|refactor|perf|build|ci|chore|test|revert)(\(.*\))?!?:'
```

Until the first release tag exists the entries below are maintained from those commit titles by
hand, so a reviewer can check any line against `git log`. Nothing here is generated by a bot, and
nothing is written ahead of the work.

### Unreleased

#### Added

- **M0 — repository scaffold and CI.** Cargo and pnpm workspaces, the PolyForm Noncommercial 1.0.0
  licence, README/CONTRIBUTING/SECURITY/CODE_OF_CONDUCT/AGENTS/PLAN/PROGRESS/DECISIONS, and the CI
  workflows: `cargo fmt`, `cargo clippy -D warnings`, `cargo test` on a three-OS matrix, `cargo-deny`,
  `gitleaks`, TypeScript lint/typecheck/test/build, CodeQL and actionlint.
- **M1 — `warshad` daemon and state store.** Single-instance advisory lock, JSON-RPC plus a
  WebSocket event stream behind a local bearer token stored with `0600` permissions, an
  unauthenticated `/health`, and SQLite migrations for projects, runs, events, gates, artifacts,
  costs and devices.
- **M2 — provider layer.** OpenAI-compatible, Anthropic and Ollama adapters, keychain-only
  credentials, model listing, routing presets with fallback on rate limits and 5xx, a cost meter and
  per-project budgets that pause a run instead of overspending.
- **M3 — pipeline engine and gates.** Role prompts stored as versioned files, artifacts written into
  `factory/`, the four-gate state machine, and an end-to-end mock-provider test that reaches Gate C.
- **M4 — `warsha` CLI.** `init`, `new`, `run`, `status`, `logs -f`, `gates`, `approve`, `reject`,
  `providers add|list|test|remove`, `roles set`, `budget set`, `doctor`, `pair` and
  `devices list|revoke`, each with a `--json` form for scripting.
- **M5 — Tauri 2 desktop app.** Onboarding, the projects board, the run view, the gates inbox, the
  artifact viewer/editor, providers and roles settings, budgets and devices, with `warshad` as a
  sidecar.
- **M6 — remote PWA and secure pairing.** QR pairing, the end-to-end encrypted channel with replay
  protection and revocation, `warsha-relay` (which only ever sees ciphertext) and Web Push.
- **M7 — coding backends and GitHub.** Adapters for opencode, OpenHands, Claude Code, Codex CLI,
  Gemini CLI, Cursor CLI and dsh, the Goose engine as the default coder, and the GitHub flow of
  repository from template → issue → branch → pull request → check status → merge at Gate C.
- **M8 — Arabic/English i18n and RTL.** Message catalogs for both languages, full RTL layout through
  logical CSS properties, a runtime language switch, and localized CLI output.
- **M9 — packaging and releases.** A tag-triggered release workflow that builds the CLI, the daemon
  and the desktop installers for three operating systems, generates SHA-256 checksums and a
  CycloneDX SBOM, and leaves the GitHub Release as a **draft**, plus prepared-but-unsubmitted winget,
  Homebrew and Scoop manifests and the mdBook documentation site.
- **M10 — orchestrator and the Discovery interview.** A leading orchestrator agent, sixteen
  structured discovery questions across nine categories, and `factory/brief.md` signed off at Gate A.
- **M11 — skills and role packs.** Agent Skill loading pinned by commit and licence-checked, with
  permissive licences bundled under notices and copyleft kept link-only.
- **M12 — MCP support and the scout.** Per-project MCP servers with approval on first use, scoped
  permissions and revocation; a scout that searches the MCP Registry and skill catalogs and installs
  only what the owner approves, recorded in `factory/skills.lock`.
- **M13 — two desktop modes behind one toggle.** Simple mode (agent sidebar, chat, team panel,
  approval cards) and Advanced mode (lanes, event stream, diffs, file tree, terminal, task board,
  skills/MCP, costs).
- **M14 — agent safety and quality layer.** Guardrails that treat page, repo and tool content as
  untrusted data, prompt-injection detection, secret masking, a difficulty-based model router wired
  into the cost accounting, per-step traces, and eval suites that block a prompt or router change
  when they fail.
- **M15 — launch assets.** The landing page, store listing texts, the social posts calendar, the
  launch checklist, the demo script and the feedback → backlog loop.
- **M15a — website and launch.** Honest audience segments and a "no fake metrics" note on the
  landing page, the demo video shot list in `docs/launch/demo-video.md`, and this changelog page.
- **M16 — continuous development loop automation.** The routines registry with a minimal cron, the
  provider auto-update planner (off by default, notify-only or auto-install, pin/skip), the Renovate
  configuration, the Tauri updater entry, and `THIRD_PARTY_NOTICES.md`.
- **M17 — planned.** Post-launch care: crash reports, store-review ingestion, a daily Arabic summary
  push and plain-language change requests. Nothing in this section ships yet.
- **M18 — planned.** Agent workflow and context: Plan → Agent mode, the todo/`ask_user`/
  `send_message` tools, context mentions, skills as slash commands, context compaction and output
  compression.
- **M19 — planned.** Backend kit: an open-source backend driven through MCP, a standard SQL +
  storage export, and payments behind their own gate.

#### Changed

- **M5 — desktop shell.** The app window hosts both modes and reads one shared client, with the mode
  choice persisted through the Tauri config commands.
- **M5a — status strip and delivery.** The ship path is visible without opening a build log: a
  four-stage status strip, a six-check release preflight, and a web deploy button that stays
  disabled until every stage is green.
- **M5b — live preview panel (web half).** A sandboxed iframe preview with Run / Stop / Pop out, and
  click-to-point through a selector so a click can reach the agent as `@element(…)` context. The
  Android half is not built, and the panel is not mounted in the run view yet.
- **M6a — continue on server.** A handoff lifecycle that carries a run to a remote `warshad`, and a
  review-and-apply step that brings changed files back per file with backups and owner-wins
  conflicts. No transport is wired yet.
- **M8b — Simple mode spec, routines and Settings → Providers.** `docs/UI.md` §4 fixes the
  three-pane RTL-mirrored layout, the reply format and the composer, and the Simple-mode routines
  and provider screens land on top of it.
- **M14a — work protection.** Snapshots before an edit, an AI undo stack scoped to a run,
  read-before-write, worktree isolation as a policy flag, and three per-session permission modes
  shown in the status strip.
- **M14b — router additions.** Local-versus-cloud badges, Eco mode that prefers a local Ollama on
  battery or offline, per-task model defaults, a local-fallback policy, one-click setup for six
  OpenAI-compatible providers, and a "Test connection" that names whether the URL, the key or the
  model is wrong.
- **M16 — dependency and update policy.** Renovate opens pull requests weekly with auto-merge off
  and the Goose pin tracked by a custom manager; the Tauri updater is configured but has no signing
  key published, so nothing can install yet.

#### Fixed

- **M1 — daemon bring-up defects.** The JSON-RPC layer needed the `macros` feature and `ClientT` in
  scope, `request<R, Params>` takes the return type first, and `DaemonError` aggregates six crate
  errors — boxed so it stays under clippy's large-error threshold.
- **M5a — two UI test defects.** Spinners injected a `@keyframes` block through a `<style>` element,
  which jsdom's CSS parser rejects; they are now SVG circles animated with SMIL. A status-strip test
  asserted against the wrong container after a second render and is now scoped with
  `within(…).container`.
- **M8b — three documentation defects.** The `UI.md` include shim pointed one directory too high,
  two unlabelled fences made `mdbook test` compile box-drawing diagrams, and the new screens reused
  existing `providers.*` i18n keys, so their headers rendered the older screen's text.
- **M14a — `mdbook test` over illustrative snippets.** Three `rust` fences in the new chapter did not
  compile standalone; they are `rust,ignore`, matching the existing security chapter.
- **M15 — the docs site did not build.** mdBook 0.5 rejected the 0.4 keys `curly-quotes` and
  `boost-matches` (the second failure silently dropped the whole `[output.html]` block),
  `additional-css` resolves against the book root rather than `src/`, and `docs/src/README.md` was
  being written to `index.html` by the index preprocessor — overwriting the landing page. The file
  is now `docs/src/introduction.md`.
- **M16 — `apps/desktop/tauri.conf.json` did not parse as JSON.** An allowlist entry read
  `"recursive: true }`, a missing closing quote that swallowed the newline, so `tauri build` could
  never have succeeded.
- **M10–M13 — verification rule corrected.** Four milestones had been recorded as done from a bridge
  log that stopped being rewritten; the rule is now that a milestone counts only when `done.flag` is
  newer than the `run.flag` that triggered it and the `RESULT:` line is read from `result.log`.

#### Removed

- **M15 — the invalid mdBook 0.4 configuration keys.** `[output.html] curly-quotes` and
  `[output.html.search] boost-matches` are gone; `smart-punctuation` replaces the first, and the
  second had no 0.5 equivalent.
- **M15 — `docs/src/README.md`.** Renamed to `docs/src/introduction.md` so the index preprocessor
  stops claiming `index.html` from the landing page.
- **M15 — the `mdbook` and `mdbook-mermaid` npm dependencies.** Both are cargo binaries, not npm
  packages, and declaring them in `docs/package.json` broke `pnpm install`. The file now says so in
  a comment instead.
- **M16 — n8n as an automation option.** Its Sustainable Use License forbids end users building
  workflows, so it is not embedded and not offered; `THIRD_PARTY_NOTICES.md` records the decision and
  Activepieces CE (MIT core only) is the optional engine instead.

### Not in this page
